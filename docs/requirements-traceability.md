| A-07 | 押金入住时登记、退房时抵扣，超出部分线下退还不入账 | orders 字段调整 |
| A-08 | 证件号加密存储+HMAC 查重+掩码返回 | guests 表与 API 重构 |

| A-10 | 时间戳 UTC 存储；业务日期为酒店本地日历日（Asia/Shanghai）；DB/应用 TZ 一致 | 时区处理全面调整 |
| A-11 | 会话 8 小时绝对过期 | 常量调整（低影响） |
| A-12 | 预订创建时锁价（默认房型 base_price，可覆盖） | 计费逻辑调整 |
| A-13 | 房型调价不影响存量预订/在住 | 需引入价格策略 |
| A-14 | 取消/NO_SHOW 不收违约金 | 需违约金规则与订单类型 |
| A-15 | 无 OTA/渠道对接，全部手工录入 | 需渠道模型 |
| A-16 | 证件号创建后不可修改（改证件=新档案） | G4 规则调整（低影响） |
| A-17 | NO_SHOW 可标记条件简化为 `checkInDate <= 今日` | 规则调整（低影响） |
| A-18 | 允许入住日当天（含）之后办理入住，不可早于入住日 | B6 校验调整 |
| A-19 | 杂费在退房结算时一次性录入，在住期间不落库 | 需预结账模型（V2 换房/延住同批） |
| A-20 | 种子管理员不强制首登改密（登记 V2） | 低影响 |
| A-21 | 生产证书未就绪前按内网 HTTP 预案（Cookie 暂不带 Secure） | 上线阻断项，必须解决（Q-09） |

## 5. 契约冻结与变更控制

1. 本表 §2 连同 [openapi/openapi.yaml](../openapi/openapi.yaml)、[database-design.md](./database-design.md) 一起评审；**批准即冻结**。
2. 冻结后变更流程（协议实现规则 10）：提出变更 → 影响分析（本矩阵全行刷新）→ 业主批准 → 同批修改 yaml/shared/文档/测试预期 → CI 全绿。
3. 任何 Agent 发现实现与本矩阵冲突时，以冻结文档为准上报，不得反向修改文档迁就实现。
