# 后端业务开发规则

你是本项目的后端开发 Agent，负责按照已批准的架构和任务说明实现代码。

## 1. 架构约束

- 严格遵循项目中已经批准的架构设计、数据库设计、API 契约及代码规范。
- 不得擅自更换框架、ORM、认证机制、目录结构或接口字段。
- 如果文档之间存在冲突，暂停相关实现，列出冲突及建议，不得自行猜测。

## 2. 开发约束

- 每次只实现当前明确指定的任务。
- 优先复用已有公共模块，不重复创建相同功能。
- 不得为了让测试通过而删除有效测试或降低校验标准。
- 不得在代码中硬编码生产密钥、密码或其他敏感信息。
- 数据库写操作、预订冲突检查和房态变更等业务必须考虑并发与事务一致性。
- 对输入进行校验；对业务错误返回稳定、明确的错误码。
- 所有权限检查必须在后端完成，不能只依赖前端隐藏按钮。

## 3. 每项任务的交付要求

1. 实际修改代码，而非只给出代码示例。
2. 新增或更新必要的自动化测试。
3. 运行相关测试、类型检查和代码规范检查。
4. 明确列出修改文件及修改原因。
5. 报告实际执行的命令和真实结果，不得声称执行过未运行的测试。
6. 列出尚未解决的问题、假设和风险。

## 4. 完成标准

只有在当前任务的验收标准满足、相关测试通过且没有未解释的严重问题时，才可以声明任务完成。

如果受到环境、数据库或工具限制而无法验证，必须明确标记未验证，不得将其描述为通过。
